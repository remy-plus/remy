# Boat: brand study

Why boat.dev stands out, and what Remy should learn from it. Read 2026-11-05 from the live site, its CSS and its logo file. For Stage 5.

## What makes it work

**One idea, carried everywhere.** A virtual machine is a boat. The hero is a pixel-art lake. Pricing draws 50 VMs as 50 boats. The speed test is a boat race against named rivals. The closing call to action is "Set sail". An empty screen says nothing is running, nothing billed. The idea explains the product, so it never reads as decoration.

**One colour, owned.** Everything is ultramarine, `#263fa9`, in steps from `#0f1634` to `#f1f3f9`, on near-white `#fefefe`. Even customer logos are redrawn in it. A glance at any section says Boat.

**A logo that holds at any size.** Two sails over a hull, solid white, then "boat" in lower case with tight spacing. It sits large in the header, about 170 px wide, and returns at the footer. The mark also works as the race piece and the favicon.

**Three typefaces, three jobs.** Funnel Display for headlines, Inter for reading, IBM Plex Mono for anything a machine would print. Mono labels make it feel like a tool.

**The art is a hero, not a backdrop.** It fills the first screen, then melts into the white page with no hard edge. The site could have stopped at a code block and a gradient. It did not.

**Product before promises.** The first screen has the install command with macOS, Linux and Windows tabs. Below are a working demo, a replayable benchmark and a price calculator. The footer is a terminal status bar.

**Written for agents too.** The page has a full plain-text version with install commands, and sends agents to `llms.txt`.

## What to avoid

- "Most powerful" and "cheapest" break Remy's voice rules: no hype.
- "Backed by Y Combinator" is low contrast on the blue. Proof should be readable.
- Boat's look is Boat's. Remy must not use pixel seascapes, boats or this blue.

## Lessons for Remy

Remy's brand has the right manners and is too quiet to remember. It needs what Boat has: one idea that explains the product.

1. **Find Remy's one idea.** Boat's is "a VM is a boat". Remy's should come from what it does: work carried out while you are away, and proof when it comes back. Task, approval, receipt and schedule should all draw from the same idea.
2. **Make one colour unmistakable.** Signal `#A8C49A` is used too rarely to be recognised. Stage 5 should test a stronger use, or a new colour.
3. **Give the logo a mark.** The `REMY` figlet is strong large and weak small. A simple mark is needed for the favicon, phone icon and app header.
4. **Make art the first screen.** Remy's own material is ASCII and grain, which is a good match for a terminal product and nobody's copy. Try a large ASCII scene in place of a generic gradient.
5. **Show real runs.** Use real tasks, real approvals and real receipts, and the public eval numbers once they exist.
6. **Add a plain-text version for agents** to the site and `llms.txt`.

These feed the two or three directions in Stage 5. The owner picks.
