## Terminal UI & branding

- [x] Ink + React + TypeScript (Ink 8 and React 19, no JSX so it runs from source)
- [x] Custom Remy ASCII wordmark (shown at the top of the chat, with a brightness ramp in truecolor)
- [x] Consistent colors, typography and spacing (one theme module: palette, symbols, spacing)
- [x] Animated thinking indicators (spinner while a model call is in flight)
- [x] Streaming AI responses (text streams in through `onText`)
- [x] Live tool status updates (each event is printed as it happens)
- [x] Task progress indicators (step lines)
- [x] Interactive chat input (`remy` opens a multi-turn chat; earlier turns become task context)
- [x] Approval prompts (y/n in a terminal, `remy approve <id>` otherwise)
- [x] Keyboard shortcuts (Ctrl+C, Ctrl+D, Esc, Up, `/help`)
- [x] Ctrl+C and graceful interruption (stops and prints `remy resume <id>`; a tool that is already running is not cancelled)
- [x] Terminal resizing support (layout follows the window width)
- [x] Non-interactive output mode (piped output, `remy show --json`)
- [x] Reduced-animation mode (`--reduced-motion` or `REMY_REDUCED_MOTION=1`)
- [x] Limited-color terminal support (`NO_COLOR`, no color when not a TTY)
- [x] Clean error messages and recovery options

## Agent brain

- [x] Model gateway (`ModelClient`, native and JSON tool strategies)
- [x] One hosted model provider (OpenAI-compatible: OpenAI, OpenRouter)
- [x] Modular provider interface for future models
- [x] Core agent loop (event-sourced, `nextAction(state)`)
- [x] Task understanding and planning (`update_plan` for tasks with three or more steps, shown in the chat)
- [x] Tool selection and execution
- [x] Result inspection and verification (prompted to read back changes; edit tools return the changed region)
- [x] Continue until completion or blocked (step, cost and time budgets; loop guard)
- [x] Clarifying questions (`ask_user`, plain-text questions pause the task, 3-question cap)
- [x] Honest completion and failure reporting

## Tools & capabilities

- [x] File reading
- [x] File creation and editing (`write_file`, `edit_file`)
- [x] File organization within an allowed workspace (`move_file`, `delete_file`, `make_dir`)
- [x] Restricted shell command execution (`run_command`: allowlist, no shell, always approved)
- [x] Web search
- [x] Web page retrieval
- [x] Source summarization
- [x] Calculator / utility tools (`calculate`: arithmetic and date math)
- [x] Consistent tool interface (zod args, declared effect and risk)
- [x] Tool permission controls (`--auto <risks>`, `remy.config.json` tool lists)

## Task persistence & recovery

- [x] Conversation history (full history within a task; a chat is a chain of tasks that carry earlier turns)
- [x] Task history (`remy list`, `remy show`)
- [x] SQLite persistence (`node:sqlite`)
- [x] Append-only task event records
- [x] Task states (running, waiting, succeeded, failed, cancelled)
- [x] Tool call and result logging
- [x] Crash recovery
- [x] Resume interrupted tasks (`remy resume <id>`)
- [x] Safe retry handling (by effect: none / idempotent / reconcilable / unsafe_to_retry)
- [x] Duplicate-action prevention (write-ahead `tool.started`, repeat denial)
- [x] Approval records tied to specific actions (bound to `argsHash`, single use)

## Security

- [x] Restricted file access (`ScopedFs`)
- [x] Sandboxed shell execution (workspace cwd, scrubbed env, timeout, output cap, approval; not an OS sandbox, see CAPABILITIES.md)
- [x] Tool permission enforcement in code (`AuthorizedCall` minted only by policy)
- [x] Prompt-injection defenses (untrusted output taints the task; non-read actions then need approval)
- [x] Sensitive-action approvals
- [x] Validate tool arguments
- [x] Protect secrets from model context (`SecretReader`, redaction)
- [x] Prevent unauthorized or unapproved actions
