# Speed, 2026-11-15

Measured through `remy serve` with Claude Haiku 5.5 on 0G, from sending the message to the first word on the
task's event stream and to the finished answer. Timing script: POST `/api/chats/messages`, then read
`/api/tasks/:id/stream`.

| Message                              | Before (2026-11-14)                    | First word now | Done now |
| ------------------------------------ | -------------------------------------- | -------------- | -------- |
| "yo I'm back"                        | about 5 s, nothing shown until the end | 2.6 s          | 2.9 s    |
| "hi"                                 | not measured                           | 1.6 s          | 2.3 s    |
| "what's a good quick dinner tonight" | not measured                           | 2.6 s          | 3.0 s    |

What changed: a greeting is answered in one model call (what happened while the person was away is in the
situation block), and the answer streams to the browser word by word, including the `finish` tool's
`answer` as the model writes it.

Where the rest goes: the 0G route itself. A bare streamed request for "say hi", with nothing from Remy around
it, took 2.3 to 2.6 s to its first byte with Haiku 5.5, and 3.1 to 3.3 s with GPT-5 nano and GLM 5.3 Flash.
Remy's own work before the model call is small next to that. A reply in about 1 s needs a faster provider
(a direct provider key, or a low-latency host); the code no longer stands in the way.
