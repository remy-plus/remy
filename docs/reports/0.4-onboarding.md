# 0.4 onboarding: report

Branch `onboarding-0.4` (from main), not merged, nothing published, version unchanged (0.3.0).

## What was built

A first-run tour, a local profile, and personalisation of the home screen and (optionally) the model's context.

- Tour: welcome, name, goals (pick several or type your own), "use this to personalise replies?" (default yes), provider (skipped when connected), model (skipped when there is nothing to pick; cheap default highlighted), a real first task, three keys, home. Esc skips the rest at any step and marks onboarding done.
- First task by goal: research, files (six sample files made first; shows an approval card before moving), coding (sample `script.py`), work and email, school. Runs with the user's model in `REMY_HOME/workspaces/tour_<id>`, in the normal session view. Enter on an empty prompt continues, Esc ends the tour (stopping the task), `S` on the offer passes it over. The practice task is cleared from the home screen afterwards.
- Profile: `REMY_HOME/profile.json` (0600) with `name`, `goals[]`, `createdAt` and `personalise`. Name and goals are cleaned on write and read (one line, letters, numbers and light punctuation). It personalises the greeting, prompt examples and every other tip. The one-line context ("The user's name is Sam; they mostly want help with research.") is appended to the system prompt at call time by the model stand-in, only when `personalise` is on; it is not stored in task events or debug logs.
- `/profile` (name, goals, personalise, delete with confirmation) and `/tour` (replay, starts from saved answers).
- Minimal mode: same steps as left-aligned plain text, the chat's own login and model panels, same first task.
- Design: pure logic in small tested modules (`goals`, `greeting`, `profile`, `onboarding`), a controller (`onboarding-flow`) over the chat, thin views (`onboarding-ui`, `onboarding-view`, `profile-ui`). No new dependencies. Typed answers are the user's words; pasted text is stripped to one line and never reaches the hidden prompt.
- Fix found on the way: picking a model closed its panel before the result was committed; it now closes together with the result.

## Known gaps

- The provider and model steps were not captured: the fake model needs no login, so they are skipped. Their behaviour is covered by controller and walkthrough tests, not by a live run.
- Not run against a real model or a real first login (needs the owner's key).
- The scratch folders (`workspaces/tour_*`) and the abandoned first task (resumable in `/sessions`) are not cleaned up.
- `/tour` after a first task clears the conversation; without a task it leaves it alone.
- Esc at the model list ends the tour (it cannot be told apart from "keep my model"); picking a model is the way forward.
- A custom goal is typed text that reaches the model as a quoted phrase; it is restricted to 60 characters of plain characters, not otherwise filtered.
- No `remy profile` subcommand and no profile sync (local only, by design).
